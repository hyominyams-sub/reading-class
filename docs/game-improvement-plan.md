반영한 사용자 결정: 성취기준은 전체 방향으로 유지한다. 게임은 이야기의 주제·핵심 사건·시나리오와 학생의 이해를 중심으로 설계한다. 특히 활동 2는 이미 읽은 내용을 쉽고 재미있게 되짚는 데 집중한다. 성취기준의 문구를 게임 단계나 필수 응답 항목으로 하나씩 옮기지 않는다.

운영 배치가 확정되지 않아도 세 게임을 독립적으로 개발할 수 있다. 기존 QR 주소와 게임 번호를 유지하고, 강제 순서 잠금이나 다른 게임의 응답을 필수로 요구하는 기능은 추가하지 않는 안으로 계획한다. 세 게임을 활동 2 안에서 수행하는 구성은 잠정 권장안이며, 사용자 확정 사항으로 취급하지 않는다.

원문이 없는 상태에서는 질문의 구조와 응답 기능을 먼저 완성한다. 아래 문항은 수업용 발문 제안이며 원작의 인용문이 아니다. 갈등의 원인, 고문서의 내용, 사건의 정답을 임의로 만들어 원작 사실로 게시하지 않는다. 원문에 의존하는 문항은 내용 확인 후 최종 적용한다.

이름은 원작 표기와 문장 속 읽기 표현을 구분한다. 인물 목록에는 ‘태현’을 사용할 수 있지만, 문장에서는 ‘태현이는 왜 그랬을까요?’, ‘태현이가 한 말’, ‘태현이의 마음’, ‘태현이에게’, ‘태현이와 연우’처럼 쓴다. ‘연우는·연우가·연우의’, ‘루미는·루미가’처럼 이름에 맞게 조사와 표현을 선택한다. 모든 이름에 ‘이’를 일괄 추가하거나 ‘루미이는’처럼 중복하지 않는다. 학생에게 보이는 발문·선택지·해설·안내·대체 텍스트를 소리 내어 읽는 기준으로 검수한다.

책의 장 순서는 대화 → 삶과 연결 → 질문과 점검이다. 공개수업의 활동 순서는 상황 이야기 → 읽기 되짚기 → 보물의 의미와 다짐이다. 게임 번호를 책의 장 번호나 공개수업의 활동 번호와 동일시하지 않는다.

세 게임을 모두 활동 2에서 운영한다면, 활동 1에서 나눈 상황을 게임에서 다시 살피고 활동 3에서 보물의 의미와 실천을 함께 나눈다. 이 경우에도 성취기준을 이유로 모든 게임에 예상·자기 점검·비교 응답을 덧붙이지 않는다. 읽은 장면을 알아보고 핵심 내용을 다시 떠올리는 경험을 우선한다. 각 문항의 짧은 해설로 자연스럽게 내용을 확인한다.

미션 3이 공개수업 활동 3 자체라면 글쓰기 마지막에 실천 한 문장을 포함한다. 세 게임이 활동 2에 묶이면 실천 문장은 기본적으로 교사와 함께하는 활동 3으로 넘긴다. 이 차이는 글쓰기 설정으로 관리할 수 있게 한다.

**4. 미션 1 — 상대의 처지를 헤아리는 선택 모험**

유지할 조작은 장면 읽기 → 선택 → 피드백 → 다음 장면이다. 뚱이는 안내자로 두고, 태현이와 연우는 원작의 인물로 표현한다. ‘뚱이가 되어 행동하기’와 ‘태현이나 연우에게 알맞은 말 고르기’를 혼용하지 않도록 발문을 장면별로 지정한다. 인물의 마음을 길게 분석하게 하기보다 읽었던 갈등 장면에서 어떤 말을 건네면 좋을지 선택하게 한다.

| 단계 | 학생 화면과 발문 제안 | 응답·피드백 | 자료 조건 |
|---|---|---|---|
| 도입 | 장대공원에서 두 사람이 나눈 실제 말과 상황을 짧게 읽는다. | 아직 누구의 잘못인지 판정하지 않는다. | 실제 갈등 대목 |
| 선택 1 | ‘태현이는 왜 이렇게 말했을까요?’ | 읽었던 상황에서 말의 까닭을 떠올린다. | 태현이의 행동·대사 |
| 선택 2 | ‘그 말을 들은 연우는 어떤 마음이었을까요?’ | 상황과 표정에 어울리는 마음을 고른다. | 연우의 행동·대사 |
| 선택 3 | ‘상대의 말을 듣고, 어떤 말을 건네면 좋을까요?’ | 상황에 알맞은 실제 대화 표현을 선택하고 이유를 확인한다. | 원작 상황에 맞는 수업용 대사 초안 |
| 마무리 | 두 친구가 화해한 장면과 짧은 설명을 읽는다. | 추가 작문 없이 완료. 짝에게 선택한 말을 해 보는 수업 연결 가능 | 갈등과 화해의 실제 결말 |

선택지 설계 기준:

- 한 장면에 세 선택지를 기본으로 한다. 무관한 사물이나 터무니없는 행동으로 정답을 쉽게 드러내지 않는다.
- 예의를 지키는 선택이 여러 개이면 복수로 인정한다. 감정이나 해석을 하나의 정답으로 단정하지 않는다.
- ‘미안해’만 넣은 선택보다 상대의 처지를 반영한 말인지 살핀다. 구체적인 대사와 이유는 실제 갈등 원인 확인 후 작성한다.
- 적절한 선택은 ‘그 말이 상대의 어떤 마음을 헤아렸는지’를 설명한다. 재고가 필요한 선택은 비난 대신 놓친 입장과 다시 살필 대목을 안내한다.
- 원작 그대로의 화해 장면과 게임에서 가정한 대화 결과를 구분한다. 다른 선택을 했다는 이유로 원작의 실제 결말까지 바뀌었다고 서술하지 않는다.
- 자동 채점은 선택 응답의 참고 자료다. 실제 예의 있는 대화 수행은 수업 중 말 주고받기에서 확인한다.

동작 계획:

- 적절한 선택에도 피드백 화면과 ‘다음 장면’ 버튼을 둔다. 현재처럼 즉시 이동하지 않는다.
- 다시 고르는 동안 첫 선택을 보존하고, 최종 선택과 재고 횟수를 별도로 기록한다.
- 다음 장면 버튼의 연속 입력으로 한 장면이 두 번 처리되지 않게 한다.
- 마지막에는 ‘살펴본 마음’, ‘선택한 말’을 보여준다. ‘한 번에 지혜롭게 골랐어요’처럼 첫 시도만 칭찬하는 문구는 바꾼다.

예상 소요: 2~3분. 읽기 길이와 학생 체험으로 확인할 계획값이다.

**5. 미션 2 — 읽은 내용을 되짚는 루미 러너**

점프, 2단 점프, 슬라이드, 장애물 통과, 수집, 마지막 관문의 기본 재미를 유지한다. 루미 스프라이트도 재사용한다. 활동의 중심은 ‘읽었던 이야기를 기억하며 달리기’다. 기존처럼 달리다가 짧은 객관식 문제를 만나고, 답과 해설을 확인한 뒤 계속 달린다.

4국02-03은 연계 성취기준으로 유지한다. ‘무엇이 궁금한가요?’처럼 자신의 질문을 고르게 하거나 예상과 점검을 별도 단계로 제출하게 하는 이전 안은 사용하지 않는다. 학생이 이미 읽은 이야기에서 답을 찾을 수 있는 직접적인 내용 확인 질문으로 바꾼다.

문제는 기본 4개, 각 문제의 선택지는 3개로 계획한다. 한 문제에는 한 가지만 묻는다. 2~4장의 핵심 장면을 돌아보며, 고문서 한 대목에 문제 전부를 묶지 않는다. 정확한 배분과 정답은 최종 원문에서 중요한 사건을 확인해 정한다.

| 문항 | 되짚을 내용 | 쉬운 발문 초안 | 선택지 구성 |
|---|---|---|---|
| 1. 인물·장면 | 2장 장대공원의 갈등 | ‘장대공원에서 다툰 두 친구는 누구였나요?’ | 인물 이름 두 개씩, 세 보기 |
| 2. 사건 | 3장 범암마을에서 일어난 중요한 일 | ‘범암마을에는 어떤 일이 있었나요?’ | 원작에서 확인한 사건과 쉽게 구분되는 다른 사건 |
| 3. 행동·단서 | 4장 고문서와 관련한 중요한 행동이나 내용 | ‘고문서에는 어떤 내용이 있었나요?’ 또는 ‘{인물이} {행동한} 까닭은 무엇인가요?’ 중 하나 | 원작이 직접 뒷받침하는 짧은 내용·이유 |
| 4. 핵심 흐름 | 이야기의 중요한 다음 사건이나 결말 | ‘{중요한 사건} 다음에는 어떤 일이 일어났나요?’ | 원작의 핵심 장면 세 개를 짧게 표현 |

1번의 구체적인 보기 예시:

> 장대공원에서 다툰 두 친구는 누구였나요?\
> ① 태현이와 연우  ② 루미와 뚱이  ③ 태현이와 루미\
> 해설: 장대공원에서 태현이와 연우가 다투었어요.

이 예시는 사용자가 제공한 장면 요약에 근거한 초안이다. 최종 출제 전 본문에서 인물 관계와 표현을 확인한다. 2~4번은 사건·고문서·결말의 세부가 아직 없어 정답과 오답을 임의로 완성하지 않는다.

문항 작성 기준:

- 앞에서 읽거나 수업에서 이야기한 내용만 출제한다. ‘누가’, ‘어디에서’, ‘무슨 일이’, ‘왜 그랬는지’처럼 바로 이해할 말을 쓴다.
- 첫 문항은 쉽게 시작하고, 뒤에서도 복잡한 추론·긴 독해·메타인지 용어를 요구하지 않는다. ‘근거’, ‘예측’, ‘읽기 과정 점검’은 학생 화면의 필수 용어로 쓰지 않는다.
- 네 문제 중 대부분은 인물·사건·중요한 단서 확인으로 구성한다. 까닭을 묻는 문제를 넣으면 원문에 분명히 제시된 쉬운 이유 한 개만 묻는다.
- 질문은 짧은 한 문장, 보기는 단어나 짧은 한 문장으로 쓴다. 보기 길이가 정답의 단서가 되지 않도록 맞춘다.
- 한 문항의 보기는 모두 같은 종류로 맞춘다. 인물 질문에는 인물, 사건 질문에는 사건을 제시한다. 복수로 맞는 보기를 만들지 않는다.
- ‘옳지 않은 것’, ‘모두 고르기’, 이중 부정, 사소한 날짜·숫자 암기를 피한다. 1813이라는 연도보다 그때 무슨 일이 있었는지가 우선이다.
- 추상적인 보물의 의미를 단일 정답으로 강요하지 않는다. 결말에 명시된 사실을 묻거나, 해석은 활동 3으로 이어 간다. 활동 3에서 처음 나눌 핵심 결론을 러너가 미리 확정하지 않게 한다.

화면 흐름은 **달리기 → 문제 한 개 → 세 보기 중 선택 → 정답과 짧은 이야기 설명 → 계속 달리기**다. 오답이어도 장면을 다시 떠올리게 하는 해설을 읽고 진행한다. 별도의 이유 선택·예상 입력·자기 점검 설문을 추가하지 않는다.

시간과 완료 처리:

- 문제·해설을 읽는 동안 달리기 시계를 멈추는 안을 유지한다. 브라우저가 숨겨진 동안도 정지한다.
- 120초는 달리기 상한으로 두고 총 활동 시간과 구분한다. 학생 안내에는 ‘달리며 이야기 퀴즈를 풀어요’처럼 쓴다.
- 현재 첫 문항 약 4초, 이후 약 11초 간격을 우선 유지하면 네 문제 사이 달리기는 약 37초다. 읽기와 선택을 포함해 2~3분을 목표로 실측한다.
- 달리기 상한에 도달하면 남은 퀴즈만 이어서 풀 수 있게 한다. 마지막 문제의 해설을 본 뒤 골인하고 완료를 한 번 저장한다.
- 완료 기준은 문제에 응답하고 해설을 확인하는 것이다. 만점이나 별도의 성취기준 점검 응답을 요구하지 않는다.
- 연속 답변, 시간 종료와 답변의 동시 발생, 재시작 후 남은 타이머를 검증한다.

점수와 결과:

- 기존처럼 퀴즈 정답과 달리기·수집 점수를 유지한다. 문항 네 개는 모두 일반 객관식이며 기존 `RunnerQuestion` 구조를 활용한다.
- 결과 화면에는 ‘맞힌 문제’, ‘달리기 점수’와 헷갈린 문제의 짧은 해설을 보여준다. 응답을 읽기 전략이나 메타인지 능력 점수로 바꾸지 않는다.
- 교사용 기록은 문항별 선택과 정오 정도로 제한한다. 예상·자기 점검 응답 타입과 저장 기능은 만들지 않는다.
- 보스 단계는 마지막 이야기 퀴즈로 바꾼다. 이미지가 준비되면 기존 보스 래스터 자산을 교체한다.
- 기존 공 모양 수집물은 간단한 종이 단서 모양으로 코드에서 수정할 수 있다. 이는 기존 canvas 도형 수정이며 장면 삽화를 코드 그림으로 대체하는 작업과 구분한다.

**6. 미션 3 — 책 속 상황과 내 삶을 잇는 글쓰기**

장면 고르기 → 감정 고르기 → 글쓰기 → 미리보기·제출의 기본 구조를 유지한다. 이야기의 주제와 보물의 의미를 자기 말로 짧게 쓰는 데 집중한다. 여러 분석 항목을 필수 입력 칸으로 나누지 않고, 기존 글쓰기 한 칸과 선택적인 문장 시작 도움말을 사용한다.

| 단계 | 내용 | 화면 문구·도움말 제안 |
|---|---|---|
| 장면 | 3장 범암마을과 결말에서 마음에 남은 원작 대목을 선택하거나 확인 | ‘어떤 장면이 기억에 남나요?’ |
| 마음 | 감정 1~3개 선택 유지. 자기 경험을 떠올리는 도움은 필요할 때 제공 | ‘그 장면에서 어떤 마음이 들었나요?’ |
| 짧은 글쓰기 | 내가 생각한 보물과 소중한 까닭을 한 편의 글로 표현 | ‘나에게 소중한 보물은 무엇인가요? 왜 소중한지도 써 봐요.’ |
| 미리보기 | 항목별 문장을 한 편의 글로 확인하고 수정·제출 | ‘내가 찾은 보물’ |

글쓰기 도움말의 초안:

> 내가 생각한 보물은 ______이다.\
> 나에게 소중한 까닭은 ______이다.\
> 나도 ______한 적이 있다.

세 문장을 모두 채우는 양식이 아니다. 쓰고 싶은 표현을 골라 자신의 글을 시작한다. 경험 연결과 작품 비교는 자연스럽게 돕되 별도의 필수 분석 단계로 만들지 않는다.

설계 기준:

- 기억에 남은 장면을 바탕으로 보물과 그 까닭을 생각하게 한다. 자신의 경험이나 비슷한 상황을 쓰는 것은 도움말로 제안하며, 공통점·차이점 칸을 따로 제출하게 하지 않는다.
- ‘보물’은 금전적 물건으로 미리 고정하지 않으며, 우정이나 협력 등 특정 추상 가치도 원작 확인 전에 정답으로 정하지 않는다.
- 학생에게 태풍 피해 경험을 전제하지 않는다. 관련 소식을 듣거나 학교·가정에서 대비했던 경험도 인정한다.
- 직접 떠오르는 경험이 없으면 ‘소식을 듣거나 본 경험’을 떠올릴 수 있도록 도와준다. 가정한 상황을 실제 경험으로 저장하게 하지 않는다.
- 기존 30자 기준은 기능 작업 초기에 유지하되 실제 학생 입력으로 확인한다. 여러 필수 필드를 추가하지 않는다. 글자 수를 내용의 질로 해석하지 않고 보물과 까닭을 쓰도록 짧은 도움말을 제공한다.
- 자동 채점이나 생성형 평가 기능은 이번 범위에 넣지 않는다. 학생의 글은 교사가 읽는다.
- 완성 문장을 그대로 복사할 수 있는 모범답안 대신 시작 표현만 제공한다.
- 기존 날짜·날씨 칸은 작은 보조 요소로 두고 보물과 소중한 까닭을 쓰는 발문보다 앞세우지 않는다.
- 활동 3에서 따로 다짐을 나눌 경우 앱에서 다짐을 필수로 요구하지 않는다. 활동 배치 확인 후 설정한다.

예상 소요: 약 3분. 짧은 글 한 편을 기준으로 실제 태블릿 입력 속도로 검증한다.

**7. 삽화 없이 진행할 기능과 이후 이미지 연결**

| 영역 | 기능 작업 단계 | 이미지 연결 단계 |
|---|---|---|
| 이야기 장면 | 본문·선택지·응답만으로 활동 가능. 새 장면 이미지가 없으면 이미지 영역을 접는다. | 검수된 장면 PNG를 연결 |
| 미션 안내 | 기존 루미·뚱이 안내 이미지를 활용할 수 있는 곳은 재사용 | 장대공원·복사골 장면을 안내 화면에도 재사용 |
| 러너 | 현재 시각 자산을 기능 검수용으로 유지하고 자산 경로를 분리 | 배경·장애물·마지막 관문을 전용 자산으로 교체 |
| 글쓰기 | 기억에 남은 장면과 보물·까닭을 쓰는 짧은 발문 | 작품 장면과 필요할 때 볼 경험 도움 장면 연결 |
| 이미지 없는 상태 | 없는 URL을 요청하지 않고, 학생에게 ‘이미지 준비 중’이나 파일명을 노출하지 않음 | 실제 파일 존재와 로딩 검수 후 활성화 |

‘삽화를 빼고 작업한다’는 것은 가짜 원작 삽화를 SVG나 CSS로 만드는 것이 아니다. 새 래스터 삽화는 이후 반드시 `imagegen`으로 만든다. 기존 코드 기반 버튼 아이콘, 진행 표시, 단순 수집 도형은 기존 방식으로 유지·수정한다.

장면 자산은 콘텐츠의 논리적 키와 파일 경로를 분리한다. 예정 파일 경로만 넣어서 미리 깨진 이미지를 만들지 않는다. 문항 풀이의 필수 단서는 본문에도 제공하여 이미지가 없거나 로딩에 실패해도 학습을 이어갈 수 있게 한다.

신규 이미지 1차 범위는 **필수 11개 + 조건부 1개**다. 이는 생성 실행 수를 약속하는 숫자가 아니라 필요한 최종 자산 수이며, 재생성·수정본은 별도다.

| ID | 새로 필요한 이미지 | 사용 영역 | 도구 |
|---|---|---|---|
| S01 | 장대공원 갈등 | 미션 1 도입·첫 선택 | `imagegen` |
| S02 | 장대공원 경청 | 미션 1 상대 입장·대화 선택 | `imagegen` |
| S03 | 장대공원 화해 | 미션 1 마무리 | `imagegen` |
| S04 | 복사골에서 고문서를 만나는 원작 장면 | 미션 2 안내·4장 내용 퀴즈 | `imagegen` |
| S05 | 고문서 세부 | 미션 2 문서 내용 퀴즈·짧은 해설 | `imagegen` |
| S06 | 범암마을의 원작 사건 장면 | 미션 3 장면 선택·본문 | `imagegen` |
| S07 | 오늘날 태풍 관련 경험 장면 | 미션 3 비교 도움 | `imagegen` |
| R01 | 복사골 픽셀 배경 | 러너 canvas | `imagegen` |
| R02 | 지상 장애물 | 기존 지상 적 교체 | `imagegen` |
| R03 | 공중 장애물 | 기존 공중 적 교체 | `imagegen` |
| R04 | 마지막 고문서 관문 | 기존 보스 교체 | `imagegen` |
| S08 | 보물의 의미를 되새기는 결말 | 전체 완료 화면, 필요할 때만 추가 | `imagegen`, 조건부 |

S01~S06은 원작 장면과 캐릭터 참고가 필요하다. S07은 오늘날 경험을 돕는 수업용 새 삽화이며 원작 장면이라고 표시하지 않는다. R01~R04는 게임용 시각 요소로, 원작에 실제 장애물이나 관문이 등장한다고 주장하지 않는다. S08은 결말과 보물의 의미를 확인한 뒤 필요 여부를 결정한다.

러너 퀴즈가 2~4장을 돌아보므로 장대공원 문제에는 S01~S03, 범암마을 문제에는 S06, 고문서 문제에는 S04~S05를 재사용한다. 문제마다 새 이미지를 추가 생성하지 않는다. 정답을 바로 보여주는 그림은 답변 이후 해설에서 사용하며, 이미지가 없어도 문제를 풀 수 있게 쓴다.

각 자산의 전체 프롬프트·화면 비율·참고 이미지 역할·최종 저장 예정 경로는 [이미지 제작 프롬프트 계획](/Users/user/task/reading-class/docs/game-image-prompts.md)에 있다.

저장은 현재 `MissionResult.details` 확장을 우선 사용한다. 새 데이터베이스나 외부 평가 서비스를 추가하지 않는다.

| 기록 | 추가할 핵심 내용 | 호환성 |
|---|---|---|
| 공통 | `contentVersion`, `schemaVersion`, 활동 식별 정보 | 버전이 없는 기존 기록도 읽기 가능 |
| 선택 모험 | `sceneId`, 첫 선택, 최종 선택, 재고 횟수 | 기존 `firstTryCorrect`, `decisionScenes`, `wrongCount` 요약 유지 가능 |
| 러너 | 문항 ID, 고른 보기, 정오, 실제 총 `timeSec`와 달리기 시간 | 기존 `score`, `coins`, `correct`, `answered`, `total` 유지. 네 문항 모두 같은 객관식 방식으로 집계 |
| 글쓰기 | 선택한 장면·감정, 보물과 까닭을 쓴 완성 글 | 기존 `sceneId`, `feelings`, `text`, `chars`를 유지하며 새 분석 필드는 만들지 않음 |

`score` 필드는 기존 저장 형식 때문에 유지할 수 있지만, 글쓰기 완료 점수를 성취 수준으로 표시하지 않는다. 교사용 화면에서는 어떤 내용을 기억했고 어떤 문제를 헷갈렸는지, 어떤 글을 썼는지를 확인한다. 성취기준 달성도를 자동 산출하는 기능은 추가하지 않는다.

새 수업의 완료 상태는 콘텐츠 버전으로 구분한다. 예전 예시 미션을 끝낸 사실만으로 새 미션이 완료되었다고 표시하지 않는다. 기존 기록은 읽을 수 있게 두며 데이터를 자동 초기화하지 않는다. 현재 저장소는 미션별 최신 결과 하나를 저장하므로, 재제출하면 최신 결과로 바뀌는 기존 동작을 유지한다. 전체 시도 이력 보존 기능을 추가했다고 약속하지 않는다.

구현 전에 설치된 Next.js의 관련 로컬 문서를 읽는다. 이미지·정적 자산 문서는 현재 확인했으며, 실제 변경 파일에 따라 클라이언트 컴포넌트·라우트 관련 가이드를 추가 확인한다. 이번 계획을 위해 패키지 업그레이드는 하지 않는다.

**9. 진행 순서와 완료 기준**

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 0 | 사용자 수정 방향 반영과 나머지 운영 검토 | 이야기 중심·쉬운 내용 확인·자연스러운 이름 표현은 반영 완료. 세부 운영은 별도 |
| 1 | 콘텐츠와 기록·자산 구조 | 새 이미지 없이도 기존 게임을 실행할 수 있고, 이전 기록을 읽을 수 있음 |
| 2 | 선택 모험 개선 | 첫 선택 보존, 모든 선택 피드백, 재고와 완료 흐름 정상 |
| 3 | 러너 개선 | 핵심 내용 객관식 4문항·3지선다·짧은 해설. 읽는 중 시간 만료로 응답이 사라지지 않음 |
| 4 | 글쓰기 개선 | 보물과 소중한 까닭을 짧은 글로 쓰고 미리보기·제출 가능 |

순서 6의 원문 자료가 먼저 확보되면 기능 작업과 함께 반영한다. 자료가 늦으면 기능 검증을 계속하되 원작 정답 문항의 확정을 완료했다고 보고하지 않는다. 기능 완료와 이미지 완료를 구분해 전달한다.

검증 항목은 실제 동작 변화에 집중한다.

- 선택 모험: 여러 적절한 답, 첫 선택 보존, 다시 고르기, 마지막 장면, 연속 클릭.
- 러너: 4문항·3지선다, 문항별 단일 정답과 해설 일치, 퀴즈 중 시간 정지, 숨겨진 탭에서 시간 정지, 시간 종료 시 남은 문제, 재시작, 완료 1회, 터치와 Space·↓ 조작.
- 글쓰기: 빈 글과 기존 글자 수 기준, 한글 입력 중 조합, 앞 단계로 이동 후 보존, 미리보기와 저장 원문 일치.
- 문구: 태현이는·태현이가·태현이의 등 자연스러운 이름 표현, 연우·루미 등 다른 이름의 조사, 한 문제에 하나만 묻는지, 해설이 길거나 추상적이지 않은지 확인.
- 기록: 학생·게스트 분리, 이전 기록 읽기, 새 수업 완료 구분, 저장 실패 후 재시도. 연결된 실제 학급 시트에 검증용 학생을 임의로 추가하지 않는다.
- 화면: 태블릿 가로·세로에서 본문과 선택지가 읽히고 스크롤 가능. 이미지 없는 상태에서 빈 대형 패널이나 깨진 이미지가 없음.
- 구현 검증: 변경 후 TypeScript 검사, lint, production build, 세 게임의 주요 브라우저 흐름. 시계·완료·기록 집계는 동작을 검증하는 작은 테스트를 사용하고 문구 변경만을 위한 테스트는 만들지 않는다.
- 이미지 연결 뒤: 21:9·2:1·작은 썸네일에서 인물·단서가 잘리지 않음, 러너 배경 경계와 실제 충돌 영역 확인.

세 게임의 활동 시간은 합계 약 7~9분, QR 이동을 포함하면 약 9~11분을 1차 목표로 잡는다. 보장 시간은 아니며 학생의 읽기·입력 속도로 리허설 후 조정한다.

**10. 검토할 결정과 미확인 입력**

| 결정 | 추천안 | 달라지는 작업 |
|---|---|---|
| 공개수업 안의 게임 배치 | 세 게임은 독립형으로 유지. 활동 2에 묶는 운영은 잠정안 | 마무리 다짐을 앱에 넣을지, 수업에서 나눌지 |
