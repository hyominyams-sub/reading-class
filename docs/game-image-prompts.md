게임 이미지 제작 프롬프트 계획 · 2026-09-10

상태: 프롬프트 초안만 작성. 이미지 생성 도구는 호출하지 않았고 아래 PNG 파일은 아직 존재하지 않는다. 사용자 요청에 따라 삽화 제작은 보류한다. 기능 변경은 [게임 개선 세부 계획](/Users/user/task/reading-class/docs/game-improvement-plan.md)을 따른다.

사용자 수정 반영: 삽화는 이야기의 주제·핵심 사건·시나리오를 떠올리게 하는 데 사용한다. 러너는 읽은 내용을 되짚는 쉬운 객관식이므로, 학생이 질문을 만들거나 예상·자기 점검을 수행하는 별도 화면용 이미지를 만들지 않는다. 장대공원·범암마을·복사골의 기존 계획 컷을 해당 퀴즈의 장면 기억과 해설에 재사용한다. 정답을 직접 드러내는 컷은 답변 이후에 보여준다.

학생 화면의 이름 표현은 ‘태현이는·태현이가·태현이의·태현이와’, ‘연우는·연우가’처럼 자연스럽게 쓴다. 생성 이미지에는 문자를 넣지 않으므로 실제 문장과 이름 표현은 UI의 발문·해설·대체 텍스트에서 검수한다. 참고 목록의 ‘태현·연우’는 원작 인물 식별 표기로 유지한다.

**제작 도구와 저장 원칙**

- 아래에서 생성 대상으로 지정한 모든 장면·배경·장애물·관문은 반드시 [imagegen 스킬](/Users/user/.codex/skills/.system/imagegen/SKILL.md)의 **내장 `image_gen` 도구**로 생성한다.
- CLI/API 경로는 이번 계획에 포함하지 않는다. 기본 경로는 별도 API 키를 요구하지 않는다. 내장 도구 실패 시 임의로 다른 생성 서비스나 CLI로 전환하지 않는다.
- 서로 다른 자산은 개별 프롬프트로 한 개씩 생성한다. 자산 11개를 한 장의 콜라주로 생성하지 않는다.
- 원작 이미지가 그림체·인물·장소 참고라면 `generate`로 처리한다. 기존 생성 이미지의 특정 부분을 보존하며 바꾸는 후속 요청은 `edit`로 처리한다.
- 사용할 로컬 참고 이미지는 생성 호출 전에 실제로 열어 확인한다. 각 입력 이미지의 역할을 프롬프트에 명시한다.
- 결과는 도구가 반환한 실제 경로를 확인한 뒤 프로젝트에 복사한다. 기본 저장은 `$CODEX_HOME` 아래이며, OS 임시 경로나 출력 경로 인자를 가정하지 않는다.
- 최종 채택본은 아래 예정 경로에 저장한다. 기존 파일이 있으면 확인 없이 덮어쓰지 않고 `-v2` 등 새 파일로 저장한다.
- 생성된 픽셀 캐릭터를 이번에 새로 만들지 않는다. 현재 루미 스프라이트를 재사용한다. 버튼 아이콘·진행 표시·간단한 단서 수집 도형은 기존 코드 자산으로 처리한다.

**원작 확인과 공통 표현**

사용자가 원작을 ‘명탐정 코난 스타일’로 설명했지만 원작 이미지는 아직 확인하지 못했다. 잠정 방향은 명확한 선, 표정을 읽기 쉬운 눈과 눈썹, 평면 셀 채색, 2D 추리 애니메이션의 장면 표현이다. 실제 생성에서는 원작 참고 이미지의 인물 디자인과 채색을 우선한다. 코난·란 등 다른 작품의 등장인물이나 안경·나비넥타이를 임의로 추가하지 않는다.

이야기 컷과 러너 픽셀 자산의 표현 방식은 다르게 유지한다. 기존 루미·뚱이의 캐릭터 디자인을 원작 인물의 얼굴로 바꾸거나, 원작 인물을 기존 앱의 스티커 캐릭터로 임의 재설계하지 않는다.

공통 제약:

- 그라디언트 없음. 이야기 컷은 선명한 선과 평면 색·경계가 있는 셀 음영, 픽셀 자산은 제한된 평면 색과 선명한 픽셀 경계.
- 제목·대사·정답·설명·한글·한자·효과음·로고·워터마크를 이미지에 넣지 않는다. 읽어야 하는 텍스트는 웹 UI에서 표시한다.
- 참고에 없는 인물, 소품, 사건, 범인, 보물상자, 마법 효과를 임의로 추가하지 않는다.
- 인물의 얼굴·머리·의상·키 비율은 제공된 참고와 일치시킨다. 서로 다른 장면에서도 같은 인물로 유지한다.
- 표정은 아동이 읽을 수 있을 만큼 분명하되, 한 인물을 악역처럼 과장하지 않는다.
- 원문 사실을 재현하는 컷과 수업용 새 비교 장면, 게임용 장애물을 구분한다.

**생성 재개 시 실행 순서**

1. 원작 참고 자료를 읽고 슬롯별 실제 자료와 정확한 장면 설명을 채운다. 각 참조의 역할을 기록한다.
2. 이야기 컷 S01을 먼저 생성·검수해 인물과 그림체 기준을 잡는다. 이는 제작 순서이며 매 컷마다 사용자 승인을 반복 요청한다는 뜻은 아니다.
3. 같은 인물·장소를 참조해 S02·S03을 개별 생성한다. S04→S05, S06, S07을 각각 생성한다.

5. R01과 루미를 참조해 R02·R03·R04를 개별 생성한다. 알파·작은 크기 가독성·실제 충돌 영역을 확인한다.

7. 채택 결과를 프로젝트에 저장하고 실제 크기, 참고 자료, 최종 프롬프트, 도구 반환 경로, 프로젝트 경로를 기록한다.
